# 3D 像素风场景工具链 — 方案设计

参考画面：`pixel.jpg`（3D 低模 + 像素贴图 + 高俯视透视相机 + 移轴景深 + 积雪）

## 1. 总体目标

| 模块 | 产出 | 宿主 |
|---|---|---|
| A. 场景生成 | 一键生成「小镇」「野外」两类 3D 像素场景（可设种子、尺寸、密度） | Godot 插件 |
| B. 天气 / 昼夜 | 晴 / 雨 / 雪 / 雷暴 + 24 小时昼夜循环，可挂到任意场景 | Godot 插件 |
| C. 资产生成 | 房屋、灯塔、树、路灯、篱笆等低模 + 像素贴图，导出 glTF | Blender 插件 |
| D. NPC 生成 | 原画 → 画风统一的低模角色 + 固定动画集，导出 glTF | Blender 插件（+ Godot 行为） |

## 2. 画风统一：「风格规范」是整个工具链的核心

所有模块共享 `shared/style/` 下的同一份规范，以此保证场景、天气、NPC 的画风一致：

- **调色板**：一个固定的有限调色板（当前 56 色，`shared/style/style.json`，并导出 `palette.gpl`）。所有自动生成的贴图只用调色板颜色及其之间的混合色（`Pal.mix`）。修改后运行 `python3 tools/sync_style.py` 同步到 Godot。
- **像素密度**：固定为 **32 texel / 米**（贴图上 1 个像素约等于世界里 3.1cm）。房子和 NPC 用同一密度，像素颗粒大小才一致。
- **贴图过滤**：近处最近邻（清晰的像素边缘），远处 Mipmap + 各向异性过滤（远看平滑、不闪烁）。
- **部件化**：门、窗是独立的 3D 部件（窗框、窗棂、玻璃、窗台、百叶窗、门板、门把手，见 `pw_parts.gd`），不再画在贴图上。
- **统一材质**：所有模型共用一个 `pixel_world.gdshader`，它负责：
  - 读取像素贴图并做光照；
  - 积雪：朝上的面按 `snow_amount` 一簇簇随机积起来，积满后成块；
  - 潮湿与积水：按 `wetness` 变暗，平地上长出反射天空的水洼，有雨滴和脚步涟漪；
  - 夜间自发光：窗户、灯罩按 `night_factor` 发光（每扇窗随机亮灭）；
  - 风动：起风后树冠摆动；
  - 水下焦散：浅水湖底的流动光斑。

  这些参数都是 Godot 的全局 Shader 参数，由天气系统、昼夜系统和角色统一驱动，单个模型无需逐一设置。
- **相机规范**：透视相机，FOV 约 30°，俯角约 40°。移轴景深为可选效果（默认关闭）。
- **渲染分辨率**：默认按原生分辨率渲染并开启 4x MSAA，远近都清晰；`PWPixelDisplay.pixel_mode` 可切换为约 540p 低分辨率放大的复古像素模式。

## 4. 模块 A：场景生成（Godot）

流程分两阶段：先生成「布局」，再按布局「摆放」模型。这样布局算法与具体资产解耦。

**1）布局层**：输出一张网格数据，每格带类型（道路、地块、水、森林、广场……）和高度。

- **小镇**
  1. 生成主街和支路：对矩形区域做递归切分（BSP），切分线即道路。
  2. 道路两侧划分地块，房屋正面朝向道路。
  3. 中心放一个地标（灯塔或广场），一侧生成海岸或河流。
  4. 路灯沿道路等距放置，空地按 Poisson 圆盘采样撒树。
- **野外**
  1. 用 FastNoiseLite 生成高度图，按台阶化处理成方块感地形（与参考图的体素风格一致）。
  2. 按「高度 × 湿度」划分生物群系：水、沙滩、草地、森林、岩石。
  3. 用 A* 连接若干兴趣点（营地、木屋、废墟），生成小路。
  4. 用 Poisson 采样撒树、石头和花草。

**2）摆放层**：按布局从资产目录（AssetCatalog）取模型来实例化。

- 资产目录是一个 `.tres` 资源，按类型、尺寸、标签登记模型。（P2 先直接调用占位模型生成器；Blender 资产到位（P3）后再接资产目录。）
- 每次摆放先经过 `PWPlacement` 的规则检查（地面层 + 高空层的类别间距，见 `VISUAL_SPEC.md`「摆放规则」）。
- 静态物体和植被按区块、按材质合批（`PWBatcher`），保证性能。

**编辑器面板**：可设置种子、地图尺寸、主题（小镇/野外）、各类密度，提供「生成」和「重新随机」按钮。生成结果保存为 `.tscn`，之后可以手工修改。

**P2 实现情况（已完成）**

| 文件 | 内容 |
|---|---|
| `world/pw_world.gd` | `PWWorld` 节点：主题、种子、尺寸、密度参数；`generate()`；地面高度 / 水深 / 能否站立查询；水深贴图和水面 |
| `world/pw_town_gen.gd` | 小镇：曲线湖岸 + 湖底剖面；主街 + BSP 支路（2~3 层）；路缘石在路口断开；土路通到码头；灯塔；沿路两侧排房（正门朝路、前院、门前通道、篱笆、门边灌木）；两侧交错的路灯和光斑；长椅；树（北边林带更密）、灌木、石头；水草、水下石头、鱼群 |
| `world/pw_wild_gen.gd` | 野外：两层噪声 → 平滑连续的地形（湖底、沙滩、草地、山坡之间都是缓坡）；湖 / 沙滩 / 草地 / 森林 / 岩石按顶点权重在 shader 里混合；陡坡不可通行；兴趣点脚下压平；营地（篝火 + 原木凳）/ 木屋 / 废墟；A* 小路（避开水和陡坡，越陡、森林和岩石代价越高，路面贴着地形起伏）；按地表撒树、灌木、石头 |
| `world/pw_placement.gd` | 摆放规则与校验 |
| `world/pw_batcher.gd` | 合批 |
| `editor/pw_world_dock.gd` | 编辑器右侧面板「Pixel World」：主题 / 种子 / 尺寸 / 树木 / 房屋 / 灌木密度 / 路灯间距 / 带湖；生成、重新随机、另存为 `.tscn` |
| `tests/test_world_gen.gd` | 回归测试：两种主题 × 5 个种子 |

与原方案的差异：
- 湖岸是「离岸距离」解析曲线（小镇）或平滑地形的等高线（野外），没有做通用的河流。
- 撒树用「随机尝试 + 规则检查」代替严格的 Poisson 圆盘采样：效果相近，而且能同时满足树冠、灯头、屋檐等多种间距。

**占位资产**：Blender 插件完成前，Godot 侧先用代码生成占位模型（盒子房屋 + 三棱柱屋顶、锥体松树），让整条流程先跑通。

## 5. 模块 B：天气与昼夜（Godot）

插件提供两个节点：`TimeOfDay` 和 `WeatherSystem`。拖进任意场景即可生效。

- **昼夜**
  - 一天 24 小时，用曲线驱动太阳的方向、颜色、强度，以及天空和环境光。
  - 夜间：路灯 OmniLight 自动打开（节点加入 `night_lights` 组即可），窗户通过 `night_factor` 自发光，天空出现星星。
- **天气预设**：每种天气是一个 `WeatherPreset` 资源，包含粒子类型、强度、风、雾、云量、光照色调和积雪目标值。切换天气时在预设之间平滑插值。
  - **雪**：跟随相机的 GPU 粒子；`snow_amount` 逐渐上升，地面和屋顶慢慢积白。
  - **雨**：雨丝粒子 + 地面溅射；`wetness` 上升，地面变暗、出现反光。
  - **雷暴**：在雨的基础上，随机间隔出现闪电——光照瞬间增强、屏幕闪白，可选闪电模型；雷声按距离延迟播放。
  - **雾 / 阴天**：用体积雾或距离雾，同时降低整体饱和度。
- **对外接口**：`set_weather("snow", transition_sec)`、`set_time(hour)`、`time_scale`，并发出 `hour_changed` 信号，供 NPC 日程使用。

## 6. 模块 C：资产生成（Blender）

- **参数化生成器**
  - 房屋：长、宽、层数；屋顶类型（双坡、四坡）；老虎窗数量；烟囱；墙面材质（竖木板、横木板、石墙）和主色。
  - 其他：灯塔、松树（体素锥体层叠）、阔叶树、路灯、篱笆、码头、雪人、木箱等。
- **像素贴图**
  1. 按 32 texel/米 自动展 UV。
  2. 程序化绘制像素图案（木板缝、窗框、砖缝）。
  3. 量化到共享调色板，用 Nearest 过滤导出。
- **导出**：批量导出 glTF，同时写入 Godot 资产目录（类型、占地格数、标签），Godot 端自动识别。

## 7. 模块 D：角色与 NPC（Blender + Godot）

**画风定位：HD-2D**（参考《八方旅人》的做法：3D 场景 + 2D 像素角色立在其中，受场景光照和阴影影响），但角色分辨率更高：
每帧 128×128 像素、角色约 96 像素高（60 像素 / 米，约为场景贴图密度的 2 倍），细节比同类游戏的角色更精细。

**做法：Blender 里搭参数化低模 → 8 方向渲染 → 程序化转成像素画。**不逐帧手绘、也不用 AI 逐帧生成（帧间无法保持一致）。

1. **角色模板**（`blender/pixel_world_blender/sprites.py`）：约 6 头身的正常比例身体（2026-11-15 前是 3.5 头身 Q 版），部件可选——
   发型（短发、刺头、长发、马尾、秃顶）、帽子（宽檐帽、头盔）、上衣袖长、裙 / 下摆长度、披风、围巾、胡子、
   武器道具（剑、长枪、法杖、拐杖、货袋），每个部位一组三色色阶（亮 / 中 / 暗）。
2. **姿势**：不用骨骼，每帧按参数直接摆出身体（大腿 / 小腿 / 上臂 / 前臂的角度、身体起伏、披风和马尾的摆动）。
   待机 4 帧（呼吸）+ 走路 6 帧（完整步态周期）。
3. **渲染**：Workbench 正交相机，俯角 12°，每帧 × 8 个方向 × 两遍——
   材质 ID 遍（每个部位一种纯色）+ 法线遍（matcap「check_normal+y」）。2 倍分辨率渲染再 2×2 合并（部位取多数）。
4. **像素化**：用固定的左上主光算 N·L，按阈值分三档，从该部位的色阶取色（赛璐璐式硬分档）；眼睛不分档、带 1 像素高光；
   轮廓外描 1 像素边，颜色 = 相邻部位最深色与墨色各半（不是死黑）。
5. **输出**：`godot/assets/sprites/<角色>.png`（8 行方向 × 10 列帧）+ `catalog.json`（帧尺寸、像素密度、脚底原点、动画表）。
   命令：`blender -b --factory-startup -P tools/blender_build_sprites.py`，6 个预设角色约 40 秒。
6. **Godot 端**
   - `PWSpriteVisual`：Y 轴公告板 + `sprite.gdshader`（最近邻、alpha 剪切；wrap 光照，背光不发黑；进树荫会变暗；
     影子 pass 里投影板转向太阳并随高度往背光方向斜，地上投出完整人影、身上不会出现半明半暗的竖线）。
     按「角色朝向 ↔ 镜头方向」的夹角选 8 行中的一行。
   - `PWCharacter.sprite_id`：玩家角色换成像素精灵（为空时仍用低模身体）。
   - `PWNPC`：按作息活动——白天在家附近闲逛（走一段、停一会儿），天黑走回家门口进门，第二天起床再出来；
     家 = 小镇每栋房子门口 / 野外营地（`PWWorld.homes`）。没有寻路，被挡住就换目标。
   - 脚步涟漪是全局共用的 4 个槽，所有角色共用一个环形缓冲，不会互相覆盖。

**原创角色预设**：旅人剑士（玩家）、行商、村姑、学者、卫兵、长者。
**动作**：姿势是一组明确的参数（腿、手臂、前倾、扭腰、头、武器在手 / 在鞘、手上发光），内置动作和大模型写的动作都是关键帧格式
（`blender/pw_specs/poses.py`）；每个动作单独一张精灵表，Godot 端用到才加载。
**原画 → 参数**：`tools/extract_colors.py` 用 k-means 取原画主色，连同原画一起交给大模型，模型按部位挑色、选发型服装武器，写出角色规格。
**随机路人**：`charspec.random_villager(seed)` 组合发型、帽子、衣服、配饰和颜色（都在调色板范围内）。
**NPC 寻路**：`PWNavGrid` 用 `can_stand` 把场景划成 1 米网格，AStarGrid2D 求路径，所有 NPC 共用；玩家走近会转身挥手。

## 9. 已确认的决定

- **目标平台：Web 优先。**由此带来以下约束：
  - 只用 Godot 的 Compatibility 渲染器（WebGL2）。不用体积雾、SDFGI，Shader 里不用计算着色器。
  - 夜间路灯用「自发光灯泡 + 地面光斑贴片」模拟，不放大量实时点光源。确实需要实时光源时，把节点加入 `pw_night_lights` 组，由昼夜系统统一开关。
  - 重复物体用 MultiMesh 渲染；雪、雨粒子数量可在 `WeatherSystem` 中配置（默认分别为 5000 和 3500）。
  - 默认原生分辨率 + 4x MSAA；低端设备可开启像素模式（约 540p 渲染）作为主要的性能节省手段。
  - Web 导出关闭多线程（`thread_support=false`），普通静态服务器就能运行，不需要配置 COOP/COEP 响应头。
- **脚本语言：GDScript。**
- **工具版本锁定：Godot 4.7.2-stable、Blender 5.2 LTS（当前 5.2.4）。**Windows 和 macOS 使用同一版本，要求所有使用者尽量保持一致（详见 README「环境要求」）。
  - 代码只使用 Godot 4.7 和 Blender 5.2 的 API；Blender 插件的最低版本声明为 5.2.0。
  - 补丁版本一起升级；升级大版本需要先单独验证，再统一切换。
  - 脚本和插件不使用特定系统的路径或工具，保证在 Windows 和 macOS 上行为一致。
- **场景规模：**小镇约 64×64 米，野外约 128×128 米。
